# 10. Formal Grammar

## 10.1 Overview

This chapter defines the formal grammar of LLMK.

The grammar specifies the syntactic structure of valid programs.

---

## 10.2 Program

```ebnf
program =
    { import_statement }
    { type_definition }
    { function_definition } ;
```

---

## 10.3 Import

```ebnf
import_statement =
    "IMPORT"
    identifier ;
```

---

## 10.4 TYPE

```ebnf
type_definition =
    "TYPE"
    identifier
    { field_definition } ;

field_definition =
    type
    identifier ;
```

A source file shall contain at most one TYPE definition.

The TYPE name shall be identical to the source file name.

The module name shall be identical to the TYPE name.

---

## 10.5 Function

```ebnf
function_definition =
    "FUNCTION"
    qualified_identifier
    "("
        { parameter }
    ")"
    { statement }
    return_value ;

parameter =
    [ "REF" ]
    type
    identifier ;
```

Functions do not declare a return type.

The return type is determined by the final returned value.

---

## 10.6 Variable Declaration

```ebnf
variable_declaration =
      let_declaration
    | var_declaration ;

let_declaration =
    "LET"
    type
    identifier
    "="
    variable_initializer ;

var_declaration =
    "VAR"
    type
    identifier
    "="
    variable_initializer ;

value =
      expression
    | function_call
    | type_constructor ;

variable_initializer =
    value ;

return_value =
    value ;

function_call =
    qualified_identifier
    "("
        [ argument_list ]
    ")" ;

type_constructor =
    type_identifier
    "("
        [ argument_list ]
    ")" ;

argument_list =
    argument
    { "," argument } ;

argument =
      literal
    | identifier
    | member_access ;

assignment =
    assignment_target
    "="
    value ;

assignment_target =
      identifier
    | member_access ;
```

---

## 10.7 Statements

```ebnf
statement =
      variable_declaration
    | assignment
    | function_call
    | if_statement
    | match_statement
    | match_result_statement
    | for_statement
    | parfor_statement ;
```

---

## 10.8 IF

```ebnf
if_statement =
    "IF"
    expression
    function_call ;
```

---

## 10.9 MATCH

```ebnf
match_statement =
    "MATCH" expression newline
    match_case { newline match_case } ;

match_case =
      match_value function_call
    | "DEFAULT" function_call ;

match_value =
      literal
    | constant_identifier ;
```

The target expression shall evaluate to `INT`, `STRING`, or `BOOL`.

Exactly one `DEFAULT` case is required, and it shall be the final case.

Each case shall contain exactly one function invocation.

The target expression and each match value shall have the same type.

A `constant_identifier` shall resolve to a compile-time constant.

Duplicate match values are invalid.

The target expression is evaluated exactly once.

---

## 10.10 MATCH_RESULT

```ebnf
match_result_statement =
    "MATCH_RESULT" expression newline
    success_case newline
    error_case ;

success_case =
    "SUCCESS" "(" identifier ")" function_call ;

error_case =
    "ERROR" "(" identifier ")" function_call ;
```

The target expression shall evaluate to a `RESULT T` value.

The cases shall appear in the specified order. Both cases are required.

Each case shall contain exactly one function invocation.

The variable in `success_case` is bound to the successful value of type `T`.

The variable in `error_case` is bound to the standard library `Error` TYPE.

Each case variable is scoped to its corresponding case.

---

## 10.11 FOR

```ebnf
for_statement =
    "FOR"
    expression
    function_call ;
```

The current element is automatically passed as the first parameter.

The current element shall not be specified explicitly in the FOR statement.

The invoked function shall accept:

- the collection element as its first parameter
- optionally one REF TYPE parameter as its second parameter

---

## 10.12 PARFOR

```ebnf
parfor_statement =
    "PARFOR"
    expression
    function_call ;
```

The current element is automatically passed as the first parameter.

The current element shall not be specified explicitly in the FOR statement.

The invoked function shall accept exactly one parameter.

REF parameters are not permitted.

---

## 10.13 Return Value

```ebnf
return_value =
    expression ;
```

Every function shall terminate with exactly one return value.

The RETURN statement is not supported.

---

## 10.14 Expressions

```ebnf
expression =
      literal
    | identifier
    | member_access
    | unary_expression
    | binary_expression ;

unary_expression =
    unary_operator operand ;

unary_operator =
    "!" ;

binary_expression =
    operand binary_operator operand ;

operand =
      literal
    | identifier
    | member_access ;
```

A unary expression contains exactly one unary operator and one operand.

The `!` operator accepts only a `BOOL` operand and returns `BOOL`.

A binary expression contains exactly one binary operator and two operands.

A function call is not an operand of a unary or binary expression.

Expressions requiring multiple operations shall be decomposed into intermediate variables.

---

## 10.15 Type

```ebnf
type =
      primitive_type
    | type_identifier
    | modified_type ;

modified_type =
      "ARRAY" type
    | "OPTIONAL" type
    | "RESULT" type ;
```

Type modifiers are always written before the underlying type.

---

## 10.16 Design Principles

The formal grammar follows these principles.

- Small and deterministic.
- No nested executable blocks.
- Functions are the primary execution unit.
- Every function ends with a value.
- Type modifiers are written as prefixes.
