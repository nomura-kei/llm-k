# 4. Built-in Type System

## 4.1 Overview

LLMK provides a small set of built-in types.

These types are sufficient to construct all user-defined TYPEs and programs.

The language intentionally minimizes the number of primitive types to improve simplicity and readability.

---

## 4.2 Primitive Types

LLMK defines the following primitive types.

| Type | Description |
|------|-------------|
| BOOL | Boolean value |
| INT | Signed integer |
| DOUBLE | Double-precision floating-point number |
| STRING | UTF-8 character sequence |

---

## 4.3 Type Categories and Composition

LLMK types are classified into the following categories.

### Basic Types

Basic types represent individual values.

- BOOL
- INT
- DOUBLE
- STRING

### Structural Types

Structural types define how values are organized.

- ARRAY

ARRAY represents an ordered collection of values of the same type.

### User-defined Types

User-defined types are declared using TYPE.

A user-defined TYPE defines a structured data type.

### State Types

State types represent the state or outcome of a value.

- OPTIONAL
- RESULT

OPTIONAL represents whether a value exists.

RESULT represents whether an operation succeeded or failed.

### Type Constructors

ARRAY, OPTIONAL, and RESULT are type constructors applied as prefixes to an underlying type.

Each type constructor wraps the type immediately to its right.

When multiple type constructors are present, they are applied from right to left.

Examples:

    ARRAY ARRAY INT

    RESULT OPTIONAL User

    OPTIONAL ARRAY User

Type constructors may be combined when their meanings are distinct.

Structural types may be nested.

Examples:

    ARRAY ARRAY INT

    ARRAY OPTIONAL User

    OPTIONAL ARRAY OPTIONAL User

Directly nested identical state type constructors are not permitted.

Examples of invalid types:

    OPTIONAL OPTIONAL User

    RESULT RESULT User

A state type constructor may appear more than once when another type constructor separates the occurrences.

For example:

    OPTIONAL ARRAY OPTIONAL User

is valid because the two OPTIONAL constructors apply at different structural levels.

Each type constructor shall follow these composition rules.

---

## 4.4 Boolean

BOOL represents a logical value.

Possible values are:

```
TRUE
FALSE
```

Boolean values are commonly used by IF statements and logical expressions.

---

## 4.5 Integer

INT represents a signed 64-bit integer.

The valid range is:

-9223372036854775808
to
9223372036854775807

---

## 4.6 Double

DOUBLE represents an IEEE 754 binary64 floating-point value.

---

## 4.7 String

STRING represents immutable UTF-8 text.

String literals are enclosed by double quotation marks.

Example:

```
LET STRING name = "Alice"
```

---

## 4.8 ARRAY

ARRAY represents an ordered collection of values.

All elements shall have the same type.

Example:

```
ARRAY INT

ARRAY STRING

ARRAY User
```

The order of elements shall be preserved.

---

## 4.9 OPTIONAL

`OPTIONAL T` represents either:

- A value of type `T`.
- `NONE`.

An OPTIONAL value explicitly represents whether a value of the underlying type exists.

The underlying type `T` shall not be `NONE`.

Examples:

    OPTIONAL STRING

    OPTIONAL User

---


## 4.10 RESULT

`RESULT T` represents either:

- A successful value of type `T`.
- An error value of the standard library `Error` TYPE.

A RESULT value shall be constructed explicitly using one of the following forms:

    SUCCESS(value)

    ERROR(error)

`SUCCESS(value)` constructs a successful RESULT whose value has the type of `value`.

`ERROR(error)` constructs an error RESULT. The argument shall have the standard library `Error` TYPE.

The successful value type `T` shall be determined from the expected type or surrounding context. If `T` cannot be determined, the program is invalid.

`SUCCESS(NONE)` is valid when the expected successful value type is either `NONE` or `OPTIONAL T`.

When the expected successful value type is `OPTIONAL T`, `SUCCESS(NONE)` represents a successful RESULT containing an absent optional value.

In this case, the type `T` shall be determined from the expected type or surrounding context. If `T` cannot be determined, the program is invalid.

`SUCCESS(NONE)` with the expected successful value type `NONE` represents a successful RESULT with no meaningful return value.

`SUCCESS(...)` and `ERROR(...)` are language constructs, not ordinary function calls.

Examples of RESULT types:

    RESULT User

    RESULT STRING

    RESULT OPTIONAL User

    RESULT NONE

A RESULT value shall not have an implicit default value. Every RESULT value shall be constructed explicitly.

A RESULT value shall not directly contain another RESULT type. For example, `RESULT RESULT User` is invalid.

The successful value or error shall be accessed through `MATCH_RESULT`, as defined in `07.Control_Flow.md`. Direct access to a RESULT's internal value or error is not supported.

The standard library defines the `Error` TYPE. Its structure is specified separately from the language's built-in type system.

---

## 4.11 NONE

NONE represents the absence of a meaningful value.

NONE is used when:

- No value exists.
- A function has no meaningful return value.
- A RESULT succeeds without returning data.

Example:

    RESULT NONE

LLMK represents the absence of a meaningful value using the single concept of NONE.

---

## 4.12 Design Principles

The built-in type system follows these principles.

- Small and consistent.
- Explicit representation of absence.
- Explicit representation of errors.
- Deterministic behavior.
- Suitable for both humans and LLMs.
