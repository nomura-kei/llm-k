# 11. Expressions and Operators

## 11.1 Overview

Expressions compute values.

Expressions shall be simple, deterministic, and easy to understand.

An expression shall contain at most one operator.

An operator may be binary or unary.

A unary operator shall have exactly one operand.

A binary operator shall have exactly two operands.

Multiple operations shall be decomposed into intermediate variables.

Example:

```llmk
LET INT x = b * c
LET INT z = a + x
```

The following is invalid because it contains two binary operators:

```llmk
LET INT z = a + b * c
```

Parentheses shall not be used to change operator precedence.

Function calls and TYPE constructors used as operands of an operation shall first be assigned to variables.

Example:

```llmk
LET INT value = User.Calculate()
LET INT result = value + 1
```

The following is invalid:

```llmk
LET INT result = User.Calculate() + 1
```

## 11.2 INT

INT is a signed 64-bit integer.

The valid range is:

-9223372036854775808
to
9223372036854775807


INT arithmetic uses signed integer semantics.

The following operations are defined:
```
INT + INT -> INT
INT - INT -> INT
INT * INT -> INT
INT / INT -> INT
INT % INT -> INT
```

Integer division truncates toward zero.

Examples:
```
7 / 2    -> 3
-7 / 2   -> -3
7 / -2   -> -3
-7 / -2  -> 3
```

The remainder follows the same sign convention as truncation toward zero.
```
7 % 2    -> 1
-7 % 2   -> -1
7 % -2   -> 1
-7 % -2  -> -1
```

For non-zero b:
```
a == (a / b) * b + (a % b)
```
Integer division by zero and remainder by zero are runtime errors.

INT_MIN / -1 is a runtime error because the mathematical result cannot be represented by INT.

Integer arithmetic overflow is a runtime error. No wraparound occurs.

---

## 11.3 Bitwise Operations

The following bitwise operations are defined for INT:

```text
INT & INT -> INT
INT | INT -> INT
INT ^ INT -> INT
INT << INT -> INT
INT >> INT -> INT
INT >>> INT -> INT
```

```
& is bitwise AND.

| is bitwise OR.

^ is bitwise XOR.

<< is left shift.

>> is arithmetic right shift. The sign bit is preserved.

>>> is logical right shift. Zero bits are shifted into the high-order positions.
```

The right operand of a shift must be in the range 0 through 63 inclusive.

A shift amount outside this range is a runtime error.

A left shift that produces a value outside the INT range is a runtime error.

### 11.4 DOUBLE

DOUBLE is IEEE 754 binary64.

DOUBLE arithmetic follows IEEE 754 semantics.

DOUBLE values include:

- finite values
- positive zero
- negative zero
- positive infinity
- negative infinity
- NaN

The following arithmetic operations are defined:

```
DOUBLE + DOUBLE -> DOUBLE
DOUBLE - DOUBLE -> DOUBLE
DOUBLE * DOUBLE -> DOUBLE
DOUBLE / DOUBLE -> DOUBLE
```

There is no implicit conversion between INT and DOUBLE.

For example:
```
LET INT x = 10
LET DOUBLE y = 2.5
```

The following is invalid:
```
LET DOUBLE z = x + y
```

An explicit conversion is required:
```
LET DOUBLE dx = to_double(x)
LET DOUBLE z = dx + y
```

DOUBLE division by zero follows IEEE 754 semantics.

For example:
```
1.0 / 0.0   -> +Infinity
-1.0 / 0.0  -> -Infinity
0.0 / 0.0   -> NaN
```

DOUBLE overflow, underflow, signed zero, infinity, and other floating-point exceptional behavior follow IEEE 754 binary64 semantics.

---
## 11.5 DOUBLE comparison

The following comparisons are defined:
```
DOUBLE == DOUBLE -> BOOL
DOUBLE != DOUBLE -> BOOL
DOUBLE < DOUBLE  -> BOOL
DOUBLE <= DOUBLE -> BOOL
DOUBLE > DOUBLE  -> BOOL
DOUBLE >= DOUBLE -> BOOL
```

Comparisons involving NaN follow IEEE 754 semantics.

In particular:
```
NaN == NaN -> false
NaN != NaN -> true

NaN < NaN  -> false
NaN <= NaN -> false
NaN > NaN  -> false
NaN >= NaN -> false
```

The same rules apply when only one operand is NaN.

For example:
```
NaN == 1.0 -> false
NaN != 1.0 -> true
NaN < 1.0  -> false
NaN > 1.0  -> false
```

---

## 11.6 NaN

NaN is a valid DOUBLE value.

NaN is not a literal and is not a reserved word.

NaN may be produced as a result of IEEE 754 floating-point operations.

For example:
```
0.0 / 0.0
Infinity - Infinity
Infinity * 0.0
Infinity / Infinity
```

produce NaN according to IEEE 754 semantics.

For arithmetic operations, an operation involving NaN normally produces NaN.

For example:
```
NaN + 1.0 -> NaN
NaN - 1.0 -> NaN
NaN * 1.0 -> NaN
NaN / 1.0 -> NaN
```

Comparison operations involving NaN follow the comparison rules defined above.


---
## 11.7 Explicit Type Conversion

LLM K does not perform implicit numeric type conversion.

Conversion between types is performed explicitly by functions.

For example:
```
LET DOUBLE value = to_double(integer_value)
LET INT number = to_int(text)
```

Conversion from NaN or positive or negative infinity to INT is a runtime error.

For example:
```
to_int(NaN)
to_int(+Infinity)
to_int(-Infinity)
```

are runtime errors.

---

## 11.8 STRING Arithmetic

The following operation is defined:
```
STRING + STRING -> STRING
```

The + operator concatenates two STRING values.

Implicit conversion between STRING and other types is not allowed.

For example:
```
LET STRING count_text = to_string(count)
LET STRING message = "count=" + count_text
```

is valid.

The following is invalid:
```
LET STRING message = "count=" + count
```

---

## 11.9 Comparisons

For INT, the following comparisons are defined:

```
INT == INT -> BOOL
INT != INT -> BOOL
INT < INT  -> BOOL
INT <= INT -> BOOL
INT > INT  -> BOOL
INT >= INT -> BOOL
```

For BOOL, STRING, and TYPE, equality comparisons are defined:
```
BOOL == BOOL -> BOOL
BOOL != BOOL -> BOOL

STRING == STRING -> BOOL
STRING != STRING -> BOOL

TYPE == TYPE -> BOOL
TYPE != TYPE -> BOOL
```

STRING ordering is not defined.

No implicit conversion is performed for comparisons.

---

## 11.10 Logical Operators

The following logical operators are defined:

```text
BOOL && BOOL -> BOOL
BOOL || BOOL -> BOOL
!BOOL -> BOOL
```

The operands of `&&` and `||` must be BOOL.

The operand of `!` must be BOOL.

`!` performs logical negation.

`&&` and `||` use short-circuit evaluation.

INT and other types are not implicitly converted to BOOL.

Example:

```llmk
IF !enabled System.Disable()
```

The following is invalid because `enabled` is an INT:

```llmk
LET INT enabled = 1
IF !enabled System.Disable()
```

---

## 11.11 Floating-Point Inspection

The standard library provides functions for inspecting special DOUBLE values.

At minimum:
```
is_nan(value)
is_infinity(value)
```

These functions return BOOL.

NaN and Infinity do not need dedicated language literals or reserved words.
