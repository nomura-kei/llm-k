
# 8. Error Handling

## 8.1 Overview

LLMK represents recoverable failures explicitly.

The language uses the built-in `RESULT` type modifier to represent the success or failure of an operation.

A RESULT value contains either a successful value or an error value.

Errors are represented by the standard library `Error` TYPE.

Error handling is explicit and deterministic.

---

## 8.2 Error Representation

`RESULT` represents the outcome of an operation.

The construction of RESULT values is defined in `04.Built-in_Type_System.md`.

The error value of a RESULT shall have the standard library `Error` TYPE.

The structure and APIs of the `Error` TYPE are defined in the Standard Library Specification.

---

## 8.3 Error Propagation

LLMK does not provide automatic error propagation.

A function may pass a RESULT value to another function without inspecting it, provided that the receiving function accepts the corresponding type.

When a function needs to inspect the outcome of a RESULT value, it shall use `MATCH_RESULT` as defined in `07.Control_Flow.md`.

Errors are propagated explicitly through RESULT values rather than exceptions.

---

## 8.4 Design Principles

The error handling system follows these principles.

- Success and failure are explicit.
- Error handling is deterministic.
- Errors use a single standard Error TYPE.
- Automatic error propagation is not supported.
- Exceptions are not supported.
